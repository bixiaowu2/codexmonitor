# Alpha × Binance 永续合约雷达（含BSC历史研究）

Python 3.10+ 和 curl 即可，无第三方 Python 包、交易账户、API Key 或私钥。只读行情、历史研究、本地 SQLite 事件及中文 HTML 看板。不执行自动交易。云端模式可将观察信号及故障/恢复通知发送至你配置的 Telegram 和钉钉。

## 云端 v3

v3 增加假定买入参考仓、60秒目标快速检查、15分钟异动预警、重要提醒确认、每6小时候选关注排序与前瞻效果跟踪。频率、参考仓与实际成本的区别，以及新版命令以 [v3升级与效果复盘.md](v3升级与效果复盘.md) 为准。保留小时观察和链上风险字段，基础规则见 [策略与使用说明.md](策略与使用说明.md)；安装和钉钉配置见 [云端部署.md](云端部署.md)。以下原始 `radar.py scan/watch` 命令仍只运行日线模块。

## 开始使用

在解压后的 `alpha-radar` 目录执行：

```bash
python3 -m unittest -v
python3 radar.py scan --chain 56 --data live --enrich 10
# 浏览器打开 live/看板.html（静态文件；扫描后手动刷新）
python3 radar.py watch --chain 56 --data live --interval 300 --enrich 10
# Ctrl+C 停止。休眠或退出终端后不会继续监测。
```

`--chain 56` 只监控BSC；省略该参数或使用 `--chain all` 扫描各链名录，与USDT USD-M永续交集匹配。历史研究命令始终限定BSC。同符号不同链/地址不会擅自合并，进入歧义隔离。

`watch` 每轮结束后等待300秒，因此实际周期是抓取耗时+300秒。全部可匹配资产均进入表格；`--enrich 10` 仅限制历史日线、持仓量与 DEX 补充查询预算。补充查询在无行情门槛阻断的项目中按最久未检查优先轮转，避免始终只扫描榜首。当天最近已收盘日线特征可跨轮复用，过期即失效；没有完成历史计算的项目不会产生突破信号。要逐个补充可提高 `--enrich`，但会增加耗时与接口压力。

```bash
# 重现历史研究；当前研究全量约180个（取决于官方名录变化）
python3 radar.py research --data data
python3 audit_dates.py --data data
# 首次调试可以限制样本，完整报告不要加 --limit
python3 radar.py research --data scratch --limit 10
```

网络使用 curl，默认验证 TLS，并遵循 `HTTPS_PROXY` / `ALL_PROXY`。不要关闭证书校验。公共接口可能有地区限制、限流、服务变更；出错写入 health.json，上一份成功快照保留但不得当成最新行情。原始响应中的 URL、抓取时间、SHA256 随报告保存。研究请求缓存24小时；删除/换用 data 目录可强制重新研究，实时扫描不复用缓存。

## 文件

- `live/看板.html`：支持搜索的中文看板。
- `live/latest.json`：全量当前交集、候选、阻断原因、缺失项、数据错误。
- `live/radar.sqlite`：`scans` 全快照；`events` 只记录新发现交集和首次进入观察阈值，跨重启去重，同时打印本地告警。
- `live/health.json`：最后运行状态。看板显示最近**成功**的扫描，不自动读取 health；故应同时检查时间。
- `data/研究报告.md`、`research.csv`、`research.json`：历史分析、七个指定项目及全部对照明细。
- `data/raw/*.json`：可审计的原始响应及来源。

## 资产连接规则

Alpha 官方名录提供 `chainId + contractAddress + alphaId`，不再要求用户手工维护全部映射。与 USDT USD-M 永续合约通过官方 `cexCoinName` 或唯一同符号匹配，再检查单位价格偏差≤20%。多个BSC地址撞同符号时隔离，绝不猜数字前缀。合约API不提供底层链地址，因此唯一符号+价格一致仍不等于完整身份认证，准备实际投资时应复核公告中的项目名/地址。当前表格排除名录 offline、offsell、fullyDelisted 条目；历史研究不排除。

## 观察分与触发

观察分是**未经回测校准的筛选阈值，不是上涨概率、收益预测或历史相似度模型**：

- 报告流通市值≤5000万美元20分，≤1亿美元10分；报告流通比例≥30%加10分。
- 报告流动性≥10万美元15分，Alpha报告24h成交额≥10万美元10分，合约≥100万美元10分。
- 本期资金费率绝对值≤0.1%加5分；不同合约结算周期可能不同，不作跨合约年化比较。
- 最近完整日线满足前30日成交额中位数2倍、突破前30日最高价、7日涨幅0–100%、当日成交额≥10万USDT，加30分。

同时满足“≥70分 + 已计算且新鲜的放量突破 + 无行情门槛阻断”才标观察候选。突破按**日线**检查，不能定位分钟级拉升。没有信号时空候选是正常结果。

阻断包括缺关键数据、流动性不足、合约成交不足、价格单位偏差、过期的合约报价、极端资金费率、24h暴涨超过100%、极低流通比例、100倍隐含流通市值超过100亿美元等。100亿美元是可见的人工情景约束，不是资产估值上限。规则需经独立时段验证后再调整，不能用赢家样本挑最漂亮参数。

`marketCap / fdv` 是行情提供方报告的供应比例代理；聚合流动性不是可成交订单深度。DEX笔数不能替代独立买家数，持有人数不能替代筹码集中度。原始日线模块未获取完整链上安全数据。云端 v2 对可能触发的信号与实际持仓增加 GoPlus 当前安全快照；清洗后的持仓集中度、关联钱包、完整解锁日历和独立卖出模拟仍缺失，不据这些缺失字段发出安全结论。

## 历史比较的限制

1. Alpha接口无历史/已失效交易对时，研究报告用明确标注的合约价格补充双条件后观察，绝不填造Alpha现货历史；特征分组统计只含Alpha现货。Alpha 与合约谁先上线都可能；分别报告 Alpha 后、两个条件都满足后的涨幅。
2. 使用已收盘日线，固定入口，避免同根K线低高点时序和未来信息错误。90日不完整时标缺失，不能归为失败。
3. 报告盘中最大倍数、期末倍数、收盘回撤，**不把最大倍数当作可实现收益**；未模拟滑点、手续费、退出和仓位。
4. 当前名录不等于完整历史名录，仍存在幸存者偏差。listingTime/onboardDate可能受重上线/合约调整影响。
5. 现在的市值、持有人与池深度不能推断过去上涨前的相应值。真实链上前置规律还需要带时间戳的档案数据或从现在持续积累。
6. 固定日30特征分组及固定规则事件检查只是探索性证据，尚无样本外收益证明。不使用合约杠杆收益冒充币价100倍。

## 无人值守运行（可选）

推荐使用 `cloud.py` 和 `deploy/alpha-radar.service`，支持 Ubuntu 24.04 ARM64，无需 Docker。安装、Telegram 配置、排障与备份见 [云端部署.md](云端部署.md)。云端模式会自动重启、持久化消息队列、超时重试，并按默认30天清理实时记录；历史研究不清理。`radar.py watch` 仍可单独使用，但不负责 Telegram 投递。

本次上市时间审计发现UB的最早Alpha日线早于当前listingTime。主报告保留“元数据基准”，不能把日期未经核实地称为首次上市。审计文件还给出最早已观察Alpha交易日之后的价格路径，但仍不是首次上市公告证据。

在Linux上也可运行 `./start_monitor.sh` 开始BSC监控；`Ctrl+C` 停止。默认没有自动启动。程序会读取随包的历史研究，额外标记“较研究窗口峰值下跌80%以上”的风险。这是历史回撤提示，不是抄底信号；研究窗口不等于全生命周期最高价。
