# Oracle Ubuntu ARM 云端部署

支持 Ubuntu 24.04 / aarch64，使用系统 Python 3.12、curl、systemd，无需 Docker，无需开放入站端口。扫描 Binance Alpha 与 USDT 永续合约的 BSC 交集，不下单、不需要交易所密钥。

## 安装

在解压后的项目目录执行：

```bash
python3 -m unittest -v
sudo bash deploy/install-systemd.sh
sudo systemctl enable --now alpha-radar
```

默认 Telegram 关闭，监控仍运行。程序位于 `/opt/alpha-radar`；实时数据位于 `/var/lib/alpha-radar`；配置 `/etc/alpha-radar.env` 仅 root 可读。更新安装会停止服务并保留配置和数据库；更新后手动重启服务。

## Telegram 配置（只在服务器输入凭据）

1. 在 Telegram 打开官方 `@BotFather`，用 `/newbot` 创建机器人，保存 Token。给新机器人发送 `/start`；向群推送时先将机器人加入该群。
2. SSH 登录服务器，执行 `sudo nano /etc/alpha-radar.env`，在 `TELEGRAM_BOT_TOKEN=` 后填 Token，暂时保留 `TELEGRAM_ENABLED=false`。不要把 Token 发到聊天、代码库或截图中。
3. 运行以下命令，仅显示数字会话 ID 和类型：

```bash
sudo systemd-run --quiet --wait --pipe --collect \
  -p User=alpha-radar -p EnvironmentFile=/etc/alpha-radar.env \
  /usr/bin/python3 /opt/alpha-radar/cloud.py --chat-ids
```

4. 再次编辑配置，将自己的会话 ID 填入 `TELEGRAM_CHAT_ID=`，并改为 `TELEGRAM_ENABLED=true`。群 ID 通常是负数；有多个结果时选择你要接收通知的会话。nano 中 Ctrl+O、回车保存，Ctrl+X 退出。
5. 发送一条明确标注的连接测试，再启动推送：

```bash
sudo systemd-run --quiet --wait --pipe --collect \
  -p User=alpha-radar -p EnvironmentFile=/etc/alpha-radar.env \
  /usr/bin/python3 /opt/alpha-radar/cloud.py --test-telegram
sudo systemctl restart alpha-radar
```

只有看到 `Telegram accepted test message` 且收件端收到测试消息，才算完成推送验证。若使用了现有机器人且已配置 webhook，`getUpdates` 可能不可用，需从原系统获取 chat_id。不要为本程序移除其他系统的 webhook。

## 运行与通知

默认每轮完成后等待300秒再扫描，每轮轮转补充12个项目的日线等数据，最多允许单轮1800秒。不是每5分钟把所有项目的历史数据重新抓取一遍。

- 首轮建立交集基线，以后新发现交集与新进入观察阈值才产生市场事件；新发现不等于刚上市。
- 观察阈值包括新鲜的日线放量突破、评分和风险门槛；是待核查线索，不代表100倍上涨概率。
- 连续3轮失败或部分数据缺失推送一次故障提示，恢复完整扫描推送一次恢复提示。
- 消息写入 SQLite 队列，重启保留，失败退避重试；默认超过1小时的待发消息过期，不补发旧信号。断线时 Telegram 已收取但响应丢失仍可能重复，按消息编号识别；不能保证严格仅投递一次。
- 正常运行但没有新事件时保持安静。关闭 Telegram 期间仍记录事件，重新启用时可能发送尚未过期的事件。
- 默认保留30天实时快照、事件及已完成队列；保留最新快照与待投递消息，随包历史研究不删除。SQLite 删除后通常复用空间，不立即缩小文件。

常用命令：

```bash
sudo systemctl status alpha-radar --no-pager
sudo systemctl is-enabled alpha-radar
sudo journalctl -u alpha-radar -n 50 --no-pager
sudo cat /var/lib/alpha-radar/cloud-health.json
sudo tail -n 30 /var/lib/alpha-radar/scan.log
sudo systemctl restart alpha-radar
# 暂停并取消开机自启：
# sudo systemctl disable --now alpha-radar
```

`active` 只证明进程存在，还应确认健康文件中 `scan.status=ok`、`last_good` 新鲜，并在 `latest.json` 检查扫描时间、错误数。Telegram 状态为 `disabled_waiting_for_credentials` 表示尚未启用；`ready_waiting_for_signal` 表示已启用并等待事件；`retry` 表示失败重试。连接测试不会写入运行服务的投递状态。

服务开机自启，异常退出30秒后重启，扫描超时终止本轮，监督线程卡死超过90秒退出重启。只限制本服务 CPU / 内存，不修改其他服务或防火墙。整台服务器断电、失联或 Telegram 故障时程序无法自行发送故障通知；需要更高可用性时另配外部存活检查。行情源可能限流、地区受限或变更接口，应定期检查数据质量。

## 备份

运行中不要只复制 `radar.sqlite` 而遗漏 WAL。使用 SQLite 一致性备份：

```bash
sudo python3 - <<'PY'
import sqlite3, os
from datetime import datetime, timezone
os.umask(0o077)
name = '/var/lib/alpha-radar/backup-' + datetime.now(timezone.utc).strftime('%Y%m%d-%H%M%S') + '.sqlite'
with sqlite3.connect('/var/lib/alpha-radar/radar.sqlite') as src:
    with sqlite3.connect(name) as dst:
        src.backup(dst)
print(name)
PY
```

另行保管配置文件与研究数据，配置含 Token，不应放入公开备份。备份文件不自动删除。

## Docker 备选

附带 Dockerfile / compose.yaml，可在装有 Docker 的环境运行。当前 Oracle 部署采用原生 systemd，Docker 构建未验证。不要同时运行两个实例向同一 Telegram 发相同信号。

## v2 与钉钉

云端现使用 `cycle.py` 串联日线与小时策略；任一部分失败会标为部分可用。Telegram 私聊命令、入场参考、退出提醒及机构/链上证据边界见 [策略与使用说明.md](策略与使用说明.md)。无需交易所 API Key。

已有钉钉群自定义机器人时，在服务器执行 `sudo nano /etc/alpha-radar.env`：

```ini
DINGTALK_ENABLED=true
DINGTALK_WEBHOOK=https://oapi.dingtalk.com/robot/send?access_token=替换为真实值
DINGTALK_SECRET=替换为机器人的加签密钥
DINGTALK_KEYWORD=Alpha雷达
```

推荐使用机器人的“加签”安全设置。采用自定义关键词时将 `DINGTALK_KEYWORD` 填为机器人现有的关键词（例如 `DT`），并将 `DINGTALK_SECRET` 留空；若另启用了 IP 白名单，也要允许这台服务器的出站 IP。Webhook 和密钥都只保存在服务器的受限配置，不要放入代码或聊天。

```bash
sudo systemd-run --quiet --wait --pipe --collect \
  -p User=alpha-radar -p EnvironmentFile=/etc/alpha-radar.env \
  /usr/bin/python3 /opt/alpha-radar/cloud.py --test-dingtalk
sudo systemctl restart alpha-radar
```

需确认显示 `DingTalk accepted test message` 且钉钉群收到测试，才算实际启用验证通过。配置为 `false` 时不会发送。

两渠道独立持久化、重试、去重和过期，某一渠道失败不会令另一渠道已成功的消息重发。市场信号、实际持仓的退出/风险提醒和系统故障通知同时推送到两边；Telegram 私聊命令回复只留在 Telegram。请确认钉钉群适合接收你的持仓成本与退出提醒。钉钉不处理登记命令，也不会 @所有人。

Telegram `getUpdates` 由本服务轮询，请不要让另一个程序同时轮询同一机器人。数据缺失、第三方安全源覆盖不足和采样间隔都会影响信号覆盖率。新版前瞻观察与持仓记录独立于30天实时快照保留，仍需定期备份和检查磁盘。
