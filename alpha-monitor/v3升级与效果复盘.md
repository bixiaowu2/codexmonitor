# v3：假定买入参考仓、分层监测与持续复盘

## 提醒价格与实际均价

新的小时突破或回踩入场参考会以**当时取得的新鲜报价**自动建立信号参考仓，并在消息中显示假定买入价、止损线和分批止盈参考。它不是成交记录、买入保证或自动下单。15分钟异动、仅观察、日线筛选及名录变化不会自动建立参考仓。

同一地址已有参考仓或实际登记仓时不重复建仓、不自动加仓、不重置成本。最多20个信号参考仓，达到上限会在新信号中明确说明没有新增跟踪；实际登记仓另有20个名额。旧信号不回填参考仓。

实际成交后，在 Telegram **机器人私聊**发送：

```text
/buy 完整BSC合约地址 实际买入均价
```

均价单位是 USDT/枚，不是总投入额。这会关闭同地址的假定买入参考仓，建立实际成本登记仓，并重新累计观察高点。若同地址已经是实际登记仓，修改成本前先 `/close 编号` 再登记，避免无意重复持仓。

默认固定止损15%；价格达到成本1.5倍/2倍/3倍分别提示；浮盈达到30%后启用从已观察高点回撤20%的移动止盈。仍是可调整的人工规则，并未证明是最优参数。现有 `策略与使用说明.md` 中v2的“需手工登记后才跟踪”与扫描频率，以本文v3说明为准。

## 分层扫描

- **快速通道**：独立子进程，以60秒为目标启动间隔，检查全部已登记实际/参考仓、最多24个活跃突破项目的支撑失效。慢速历史扫描不会串行挡住它。
- **15分钟预警**：快速通道每轮轮换12个通过基础过滤的项目，采用已收盘的15分钟K线。16根历史基准加当前一根，量比≥3、成交额≥5000USDT、涨幅0.5%–10%、接近/突破过去4小时高点时提醒关注。它不是入场参考，也不建参考仓。
- **名录变化**：约120秒检查 Alpha 和合约目录，首次建立基线，之后新增项才提示。原来的重复交集推送关闭，原始事件仍保存。
- **详细扫描**：每轮完成后等待180秒，小时检查预算提高至120个通过基础过滤的项目；超出预算仍轮换。不是每3分钟为所有名录币都调用全部接口。
- **前瞻结果**：主扫描与快扫描复用新鲜报价更新评估路径；主扫描另给离开筛选条件的已跟踪项目最多40个轮换报价名额。

所有频率都是目标而不是零延迟承诺；网络、接口限流和扫描耗时会影响实际间隔。快速通道超时150秒会终止该轮并重试；连续3轮异常单独告警。缺失/过期报价不用于触发止盈止损。采样之间瞬时越线仍可能漏掉。

## 重要提醒确认

固定止损、移动止盈、流动性恶化、持仓报价失效、突破支撑失效支持：

```text
/pending
/ack 重要提醒编号
```

首次发送后每5分钟补提醒，最多补3次，24小时后过期。补提醒明确标注“首次触发记录，价格不是当前报价”。确认已读不会买卖，也不会结束持仓跟踪；`/close 持仓编号` 才结束跟踪。条件恢复或关闭仓位后停止未发出的补提醒；已送达消息不撤回。重要提醒编号和持仓编号是两种不同编号。

Telegram API/钉钉 API 返回成功只说明平台接受，不等于用户已读。真正的已读确认来自 `/ack`。行情恢复后，固定止损/移动回撤/流动性条件带缓冲区重新布防，后续新的风险事件可以再提醒。

## 根据实际效果改进

每个新入场参考保存版本、信号类型、时间、报价和当时可取得的特征；每个UTC日从本轮新鲜、未阻断的样本中，用固定哈希规则抽取最多8个对照，避免按未来涨幅挑对照。对照与信号可能属于同一代币，不应当作相互独立的试验。

最长跟踪180天，记录采样峰谷、最大采样回撤、报价空档以及1/3/7/30/90/180日端点。端点超过30分钟未取得报价就标缺失，不用后来的价格回填。异常巨大跳价单独标记，不能直接当百倍成功。

服务器每日生成：

- `/var/lib/alpha-radar/evaluation-report.json`
- `/var/lib/alpha-radar/效果复盘.md`

Telegram `/performance` 查看最近报告。服务器每周发一次简短的前瞻记录概况，不每天刷屏。报告里的“触及100倍”只是采样路径，不是已实现收益；没有计算手续费、滑点和真实卖出。对照只覆盖实际观察到的样本，不能估计全市场漏检率。

已安排本任务每周日10点复盘服务健康和实际效果。定期维护需要本机和桌面应用可运行、SSH可用；云服务器上的监控与每日效果统计独立运行。依据官方说明，本地文件相关定期任务需要电脑与应用保持运行：[Scheduled tasks](https://developers.openai.com/codex/app/automations/)。

优化优先级：先修复数据/覆盖/投递问题，再考虑策略参数。参数修改需要足够成熟样本、按资产分组和按时间留出的独立验证，保留旧版本并进行前瞻比较。没有证据就不调参，不把少量赢家或事后最高点写成“提高了百倍概率”。当前没有可信的百倍概率模型。

```ini

```

`fast-health.json`、`fast.log` 是快速通道状态；`cloud-health.json` 同时包含 `scan` 与 `fast` 状态。SQLite新增字段/表为增量迁移，原记录保留。更新前备份代码和SQLite；配置文件不放入代码包。参考仓、重要提醒与长期效果数据不会按30天实时快照清理，需要定期备份与检查磁盘。

## 候选关注排序

主扫描每 6 小时从本轮取得新鲜报价、通过风险门槛的观察结果中生成前 5 名关注列表，并通过 Telegram 和钉钉推送。排序综合小时量比、接近压力位程度、小时/24小时动能、报告流动性、流通市值规模和是否匹配 USDT 永续；已有小时突破/回踩参考会说明。它是注意力排序，不是上涨概率、收益承诺或自动买入。无合格候选时也会推送空榜，避免把旧数据当新信号。`RANKING_INTERVAL_SECONDS` 可设为 1 至 24 小时，默认 6 小时。


排序版本为 focus-v1.1：Alpha＋合约交集优先，使用新鲜完整小时K线、流动性、市值/FDV、风险标记和已有入场参考；风险未知或数据过期时不凑数。
